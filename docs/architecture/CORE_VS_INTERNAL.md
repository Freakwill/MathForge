# CORE versus Internal MathForge

| Label | Meaning |
| --- | --- |
| CORE IMPLEMENTED | Present in the imported reusable CORE; only the stated scope is supported. |
| INTERNAL | Found in private code or retained research records; absent from this distribution. Some steps require human or agent review. |
| EXPERIMENTAL | A partial or optional implementation exists, with incomplete end-to-end qualification. |
| PLANNED | A design, contract or external future step; no implemented automatic capability is asserted. |

Implementation labels are independent of scientific outcomes. A gate PASS is scoped permission or evidence, not proof of originality or publication. INTERNAL does not mean currently running or universally automated. Solid arrows describe observed component handoffs or reviewed workflow order; dashed arrows denote optional or future handoffs, never a promise of automatic execution.

The reviewed extraction baseline is **58 files / 205,023 bytes**. This repository additionally retains its initialization LICENSE, brand images, provenance and documentation. Its total size must not be advertised as a 205 KB distribution. The historical engineering CORE inventory and private recovery archives are different assets and were not uploaded.

## Verification boundaries

The imported implementation passed all 29 local tests, including real Lean synthetic positive and negative checks, in a fresh isolated environment. The initial import GitHub Actions checks passed; cloud tests run 29 cases with the explicit real-Lean integration skipped when no reviewed toolchain is configured. CI exercises synthetic infrastructure only.

Private components were inspected read-only for this map. Their existence or historical receipts do not mean they were rerun, independently scientifically certified, continuously running, or released here. Ten role contracts are responsibilities, not evidence of ten active autonomous agents.

The private foundational Phase 0 policy still disables research execution; additive internal execution authorization is scoped to separate modules. Importing these documents does not broaden that scope or enable any research process.
